## 阶段 D 容量规划实施计划

### 1. 数据库与领域模型
1. 在 `location` 表增加 `capacity INT NOT NULL DEFAULT 0`，并同步 `Location` 实体、地点管理前端表单/列表与后端校验。
   - `0` 表示尚未维护容量；容量统计时不纳入有效教室。
   - 新增、修改、删除地点后，在 Service 层重算学校画像中的教室容量范围。
2. 新增单例 `school_profile` 表及对应 Entity/Mapper/Service：
   - 学校名称/简介/办学定位/优势学科/重点方向/学生群体等文本字段；
   - `min_room_capacity`、`max_room_capacity`，默认 `0`；
   - 以单行配置方式读取，管理员可维护，后续可将读取实现替换为 RAG 数据源。
3. 为教师资料增加可维护字段（放入现有 `user` 表，避免本轮新增过多角色专属表）：
   - `title`（职称/头衔）和 `bio`（个人简介），允许为空；
   - 同步 `User`、`UserUpdateDTO`、`UserInfoDTO`、用户服务映射、教师个人中心；
   - 教师/管理员可维护，其他用户不因新增字段获得额外权限。
4. 更新 `schema.sql`：新环境建表定义与文件末尾已有库升级注释同时补齐；同步必要的 `data.sql` 默认值/插入语句，避免历史初始化失败。

### 2. 教室容量范围联动
1. 在地点 Service 中抽取“重算学校教室容量范围”方法：查询所有 `capacity > 0` 的地点，计算最小值和最大值；无有效地点时均写回 `0`。
2. 在新增、更新、删除地点成功后调用重算逻辑；使用事务保证地点变更与汇总更新的一致性。
3. 本轮不做具体教室推荐，也不改变讲座 `lecture.capacity` 的保存语义；`location.capacity` 仅作为后续推荐和容量边界数据基础。
4. 不把教室容量强行作为当前讲座报名限制，避免改变现有报名业务范围。

### 3. 容量统计服务
新增 `CapacityEstimationService`，只依赖现有 Mapper/学校画像服务/LLM 客户端，不在 Agent 工具中直接堆业务逻辑。

统计口径：
1. 只统计已结束讲座，并只统计 `registration.status = 1` 且未删除的有效报名；排除已取消报名。
2. 讲师口径：按当前讲师名称/资料匹配历史讲座，统计有效报名需求。
3. 主题分类口径：按分类 ID 统计历史讲座及有效报名。
4. 标题关键词口径：从当前标题提取稳定关键词，与历史标题匹配后统计；实现确定性、可测试的中文关键词抽取/匹配，避免引入新的搜索基础设施。
5. 每个口径低于 5 场历史讲座时不采用；统计值低于 `max_room_capacity / 3` 时不采用。
6. 将可用口径汇总为统计基准 `base`（明确返回样本量、使用了哪些口径）；没有可用历史数据时使用配置化默认容量。
7. 不使用签到率修正报名需求。

### 4. 三维语义评估与规则融合
1. 在 `AgentProperties`/`application.yml` 增加容量配置：默认容量、取整粒度 `roundTo`、历史样本阈值、三维 HIGH/MEDIUM/LOW 系数等；教室最小/最大边界从 `school_profile` 读取，不重复配置。
2. 新增结构化 LLM 评估流程，复用 `AgentLlmClient.generateText`：
   - Prompt 输入讲座标题/摘要或内容、讲师姓名及 `title`/`bio`、学校画像全文；
   - 只要求输出 `contentHeat`、`speakerReputation`、`schoolFit`、`reason`；
   - 严格校验 JSON 对象、三个枚举和理由；支持前后 Markdown 的宽松 JSON 截取与一次重试；不能使用模型输出的数字容量。
3. 学校画像为空时不臆测校本契合度，使用中性系数 `1.0`，并在结果中明确“未使用学校画像”。教师资料不足时讲师声望使用中性系数并输出不确定性说明。
4. 按以下初始系数实现并写入配置，结果中同时返回/展示计算依据：
   - 内容热度：HIGH 1.30 / MEDIUM 1.00 / LOW 0.80；
   - 讲师声望：HIGH 1.20 / MEDIUM 1.00 / LOW 0.85；
   - 校本契合度：HIGH 1.30 / MEDIUM 1.00 / LOW 0.80。
   设计说明写入文档/结果：中性档不改变统计基准；高低档限制在约 ±20%~30%，避免定性模型主导数值；校本契合度用于抑制“社会热点但与学校受众不匹配”的过度放大；讲师权重略低是因为资料稳定性通常弱于主题/学校画像。
5. 计算顺序：统计基准 × 三个系数 → 按学校最大容量做上限裁剪、按学校最小容量做下限裁剪（仅对大于 0 的边界生效）→ 按 `roundTo` 向上取整 → 再次裁剪到有效教室边界，防止取整越界。
6. 返回建议容量、统计基准、历史样本量、使用口径、三维等级/系数、学校画像是否使用、边界与取整说明、数据不足和不确定性说明。

### 5. Agent 工具与路由
1. 新增 `CapacityTools`：
   - `@AgentTool(name="estimateCapacity", domain="analysis", roles={"admin","teacher"}, type=READ)`；
   - 接收创建前必要的字符串参数（标题、摘要/内容、讲师姓名、可选分类），不接收 userId；
   - 从 `AgentContext` 获取登录身份，工具内再次校验教师/管理员权限；教师只可为本人讲师资料/讲座规划使用，管理员可跨教师；
   - 调用 `CapacityEstimationService` 并返回可解释文本，不写入 `lecture.capacity`。
2. 在 `AgentEngine` 系统提示中加入容量规划能力及“只输出建议、不自动创建/修改容量”的约束。
3. 在 `ToolRouter` 的 `analysis` 域关键词中加入“容量、容量规划、建议人数、容纳人数、设置人数、预计人数、规模”等词；补充排他描述，降低与 `queryStatistics` 的误选。保持候选集外调用拒绝机制。
4. 前端工具中文映射增加 `estimateCapacity`；本轮不新增专门容量推荐页面，保留对话入口即可。

### 6. 测试与验证
1. 新增规则服务单测，覆盖：
   - 有效报名与取消报名排除；
   - 讲师/分类/标题关键词三种口径；
   - 少于 5 场不采用；
   - 统计值低于最大教室容量三分之一不采用；
   - 无历史数据使用默认容量；
   - 三维系数融合、缺画像中性处理；
   - 最小/最大教室边界；
   - `roundTo` 向上取整及取整后再次裁剪；
   - 非法/缺失 LLM JSON 的重试与可解释降级。
2. 新增地点容量范围联动测试，覆盖添加、修改、删除地点以及无有效容量时回写 0。
3. 新增 ToolRouter/CapacityTools 权限和容量关键词路由测试，覆盖教师、管理员、学生、游客和“多少”同时命中统计域的情况。
4. 执行 Maven 编译/定向测试；若环境 Java 版本仍为 8 而项目测试类为 Java 17，记录并切换到 Java 17 后复核。执行前端构建检查新增字段契约。
