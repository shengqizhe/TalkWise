### 数据库变更（阶段 D 附带，同样未提交）
结构（`src/main/resources/db/schema.sql`）：
1. 新增表 `school_profile`（school_name 唯一，profile_content，min/max_room_capacity）
2. `location` 加 `school_name`(VARCHAR200 + idx_location_school_name)、`capacity`(INT NOT NULL)
3. `user` 加 `title`(VARCHAR100)、`bio`(TEXT)

种子（`src/main/resources/db/data.sql`）：location 11 行补 school_name='示例大学' 与 capacity(100~200)；新增 school_profile 1 行（min100/max200，与地点范围一致）。

联动：`SchoolProfileServiceImpl.recalculateRoomCapacity(schoolName)` 取该校 location 中 capacity>0 的最小/最大值回写画像；`LocationServiceImpl` 增改删后调用（改校名时新旧校都重算）。

**发现的问题（需修）**
- schema.sql 末尾升级块里 `ALTER TABLE school_profile ADD profile_content` 排在 `CREATE TABLE school_profile` **之前**，对老库执行会报"表不存在"；且该 ALTER 本身冗余（CREATE 已含该列）。
- `location.capacity` 在 CREATE 中是 `INT NOT NULL` 无 DEFAULT，升级块却是 `INT NOT NULL DEFAULT 0`——不一致；且老库 ALTER 补 0 后，`capacity>0` 过滤会让画像 min/max 归零，需管理员手工填容量。
- 升级块是 `--` 注释，不会自动执行；项目**无 Flyway/Liquibase**，也无 `spring.sql.init` 配置，schema.sql/data.sql 全靠手工执行。
- 实际 MySQL 库未被改动，仅脚本层变更。
